# OpenCode Brave Bridge

Instalador para o host de mensagens nativas do Brave e configuração MCP global do OpenCode. Protocolo detalhado em [protocol/README.md](protocol/README.md). Requer Node.js 20 ou superior.

## macOS e Linux

Na cópia local do projeto, rode `sh scripts/install-unix.sh` (não usa sudo). Copia `package.json` e o lock, quando existir, instala dependências de produção na cópia (`npm ci --omit=dev` com lock; senão `npm install --omit=dev`) e cria launchers separados para `src/host.js` (Brave) e `src/mcp.js` (OpenCode). Configura o MCP global via `opencode mcp add brave --global -- <caminho-absoluto-de-launch-mcp>`. Se OpenCode CLI não estiver no PATH, execute esse comando manualmente usando o caminho impresso/instalado.

No **Brave 1.96 do macOS testado**, a busca do host nativo retornou “não encontrado” com o manifesto apenas em `BraveSoftware/Brave-Browser/NativeMessagingHosts`, mas o mesmo manifesto foi encontrado no diretório de usuário `Google/Chrome/NativeMessagingHosts`. O instalador registra **somente** `dev.opencode.brave_bridge.json` em ambos os diretórios, sem sobrescrever um arquivo diferente já existente. Esse comportamento é específico do build observado, não uma garantia para todos os Braves. O desinstalador remove a cópia de compatibilidade apenas quando os manifestos forem idênticos.

## Windows

PowerShell: `./installers/install.ps1` (não requer administrador; exige `LOCALAPPDATA`). O instalador compila `installers/host-launcher.cs` em um executável nativo com `Add-Type` (Windows PowerShell 5.1 ou PowerShell 7 para Windows); se a compilação não estiver disponível, falha com uma mensagem explícita. Brave aponta para esse `.exe` sem argumentos; o launcher ignora os argumentos fornecidos pelo navegador e lê os caminhos absolutos de `node.exe` e `src/host.js` do `host-config.json` adjacente, encaminhando stdin/stdout como bytes e mantendo stderr separado. A configuração fica em `LOCALAPPDATA` com as ACLs herdadas do usuário. O launcher MCP do OpenCode continua sendo `.cmd`. O registro fica somente em HKCU e usa JSON gerado de objeto PowerShell. Para diagnóstico/remoção use `installers/doctor.ps1` e `installers/uninstall.ps1`; o diagnóstico verifica executável, manifesto e configuração adjacente. O fluxo Windows não foi testado neste ambiente.

## Brave: instalação manual obrigatória

Abra `brave://extensions`, habilite Modo do desenvolvedor e use **Carregar sem compactação** apontando para a cópia instalada em `extension/` sob os dados do usuário. O projeto contém uma chave **pública** no campo `key` de `extension/manifest.json` para manter o mesmo ID entre computadores: `gffmhlbhkkgcmjnganoobbnjbplgehdo`. Confirme que o Brave mostra esse ID. Depois da instalação/reinstalação, clique em **Recarregar** na extensão. Não é feita automação do Brave.

Para usar em outro computador, copie/clone o projeto nesse computador e execute o instalador localmente; não copie os dados de registro entre sistemas. Instale Node 20+ e OpenCode previamente. O diretório de extensão carregado manualmente é a cópia instalada, não a árvore-fonte.

## Limites e segurança

O v2 lê status de grupo, abas e snapshots (com máscara de campos secretos e truncamento). Abrir uma aba nova (`tab.open`) sempre cria uma aba inativa; já navegar (`tab.navigate`) e clicar (`tab.click`) agem em qualquer aba do grupo autorizado, **incluindo a aba ativa**, mas nunca ativam ou trazem foco para uma aba/janela por conta própria — quem decide o que fica em primeiro plano continua sendo você. Clicar em elementos visíveis e preencher campos de texto, textarea ou conteúdo editável (`tab.fill`) a partir de um snapshot recente exigem **autorização de interação separada da leitura, por sessão e origem**, válida por até 30 minutos e revogável no popup; campos sensíveis (senha, arquivo, ocultos, e campos que pareçam cartão, token, e-mail, telefone ou código de uso único) nunca são preenchidos, e o valor digitado nunca é devolvido ao agente. Cliques e preenchimentos podem alterar dados da conta: antes de publicar, enviar, excluir ou realizar outra ação importante, o agente deve pedir sua confirmação. Não oferece cookies/storage/rede nem execução de JavaScript arbitrário; leitura, clique, preenchimento, captura de tela e upload de arquivo `.aab`/`.apk` são funções fixas e empacotadas na extensão, um conjunto deliberadamente limitado — não é uma automação de navegador completa nem busca paridade com integrações completas de agente-no-navegador. Para autorizar a leitura, selecione a sessão no popup, confira as origens HTTPS propostas e confirme; o Brave pode solicitar permissão de host. Não é necessário abrir, selecionar ou mover abas existentes. A extensão cria uma aba-semente inativa no grupo e abre futuras páginas inativas nesse grupo. Pedidos subsequentes podem propor origens adicionais, que exigem nova confirmação. Sessões distintas têm grupos distintos. Uma concessão (de leitura ou de interação) sobrevive a um recarregamento da extensão somente se o grupo de abas, a aba-semente e a permissão de host concedida continuarem intactos e idênticos; qualquer divergência descarta a concessão salva sem aviso, e a sessão volta a pedir nova aprovação. Reiniciar o navegador sempre revoga todas as concessões, leitura e interação, mesmo que os grupos de abas continuem abertos; revogar pelo popup tem o mesmo efeito imediato. O texto visível pode conter dados pessoais apesar da máscara: conceda apenas páginas que queira compartilhar. Conteúdo de páginas é dado não confiável. **Esse isolamento é organizacional, não protege contra outro programa/agente com shell rodando como o mesmo usuário**, capaz de acessar o socket local. Veja o protocolo para detalhes.

### Captura de tela (screenshot) e upload de arquivo — em progresso

Captura de tela exige uma autorização **visual** separada da leitura e da interação, por sessão, aba (handle) e origem, concedida explicitamente no popup com validade de até 30 minutos e revogável a qualquer momento. Conceder essa autorização é o que dispara o pedido da permissão opcional `debugger` do Brave — nunca solicitada na instalação — que é liberada assim que nenhuma sessão mantiver captura ativa. A imagem é um JPEG (qualidade 45) limitado a 500KB, obtido via protocolo de depuração do Chrome (`Page.captureScreenshot`). **Ressalva importante sobre redação**: diferente do `snapshot` de texto, a captura de tela grava os pixels inteiros da página renderizada, **incluindo iframes de outra origem**, e não passa pela máscara de campos secretos nem pelo truncamento aplicados ao texto. Qualquer coisa visível na tela pode aparecer na imagem; conceda apenas para uma aba/origem que você aceita ver capturada.

Upload de arquivo (`upload_file`) aceita apenas `.aab`/`.apk` de até 256MiB e segue um fluxo de três etapas explícitas — **stage (preparar) / approve (aprovar) / commit (efetivar)** — sem envio automático de formulário. Na etapa de preparo, o processo MCP copia o arquivo de origem para uma cópia local em disco em diretório de dados do usuário, com permissões restritas e validade de **30 minutos**; a extensão recebe apenas a proposta (nome, tamanho, hash SHA-256), sem tocar a página ainda. Cada proposta exige confirmação individual no popup — um clique explícito em **"Approve this file" por arquivo**, sem aprovação em lote ou permanente. Somente depois disso o agente pode efetivar: a extensão reanexa o `debugger`, define o valor do campo de arquivo identificado no snapshot e desconecta — **o formulário nunca é submetido automaticamente e nenhuma tecla Enter é enviada**. **Isso não significa que o arquivo não pode sair da página**: anexar o arquivo dispara os mesmos eventos nativos (`input`/`change`) de uma escolha manual pelo usuário, então o JavaScript da própria página passa a ter acesso imediato ao arquivo assim que o campo é preenchido — se a página já tiver um script escutando esse campo, ele pode ler o arquivo e enviá-lo para fora (por `fetch`/XHR) sem nenhuma submissão de formulário e sem nova ação do usuário; isso não é uma checagem de mesma origem que este projeto possa bloquear, pois é o script da própria página agindo na própria origem. Este projeto não publica nada no Google Play nem em qualquer outro destino por conta própria e não aciona esse envio ele mesmo, mas também não pode impedir que uma página já preparada para isso transfira o arquivo assim que o `commit` for efetivado — só aprove a etapa de commit para uma página e campo em que você confia.

**Aviso de protótipo**: as duas funcionalidades acima (captura de tela via `debugger` e upload de arquivo em duas fases) são recém-implementadas e **ainda não foram validadas em um Brave real** — apenas a lógica local foi verificada. Trate-as como não verificadas até que o smoke test manual (`extension/SMOKE_TEST.md`) seja executado com sucesso. Nenhuma delas, nem o projeto como um todo, busca paridade com uma integração completa de agente-no-navegador; o conjunto de operações continua deliberadamente restrito.

Scripts: `scripts/doctor-unix.sh`, `scripts/uninstall-unix.sh` e equivalentes PowerShell em `installers/`. Uninstall remove dados e registro do host/MCP global (`opencode mcp remove brave --global`), mas não desinstala a extensão carregada; remova-a manualmente em `brave://extensions`.

## Estado das plataformas

**macOS é a primeira plataforma-alvo.** Linux e Windows possuem instaladores iniciais no repositório, mas ainda não foram testados nesses sistemas e não são considerados versões lançadas. O host já aceita múltiplas conexões simultâneas e testes automatizados verificam o roteamento separado; a passagem real de IDs entre várias sessões OpenCode e a interação com o Brave ainda precisam de aceite no navegador. Upload de arquivo `.aab`/`.apk` e captura de tela estão implementados com fluxo de confirmação explícita (veja seção acima), mas **não foram testados em um Brave real**; nenhum dos dois publica no Google Play — o upload apenas preenche um campo de arquivo em uma página já aberta pelo usuário.
